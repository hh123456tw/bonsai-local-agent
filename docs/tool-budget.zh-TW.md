# Claude Code 顯示24次工具上限的來源

2026-11-03：已定位並改為可設定。依使用者最後選擇，目前取消總工具次數上限，保留重複工具糾正與失敗停止。先前選過的64次有限方案仍可設定。

## 確切來源

舊訊息「本輪已執行24次工具，仍未完成」由本套件的 `runtime/bonsai_proxy.py` 產生。原條件是 `len(calls) >= 24`，在請求原生引擎前直接回傳文字停止訊息；HTTP本身是200，Anthropic回應是 `end_turn`。因此Claude Code會顯示這段回覆。

本機 `guard-events.jsonl` 找到三筆相符的 `tool_budget_stop`，記錄的calls均為24。這條限制不要求工具重複，也不檢查任務實際進度；合法的長任務也會碰到。它不是Claude Code的官方24次工具限制，也不是context或GPU錯誤。

另有OpenCode專用設定 `agents.build.steps=24`，它不會被Claude Code讀取，並不是本次訊息的來源；本次依使用者選擇取消的是橋接的總工具次數限制，OpenCode自身步數設定未更動。

計數是「最近一個實際使用者輪次之後，歷史中的工具呼叫數」，包括讀檔、搜尋、執行、失敗和遭拒的呼叫。它不代表24次成功執行，也不是24則使用者訊息。Anthropic的tool_result包在user訊息內，橋接會把它識別成工具結果，不重置輪次。

## 現在怎麼調整

編輯安裝目錄的 `C:\AI\bonsai\guard-config.json`：

```json
{
  "max_tool_calls": null
}
```

`null`代表取消總工具次數上限，不需要為次數用完而手動接續。這不取消連續重複工具的檢查。若想恢復有限額度，可填1至1000的整數，例如64；不接受0或字串。每次生成請求讀取一次，新值下一次請求生效，不需要重啟引擎。不存在設定檔時也不設總次數上限；格式錯誤會回報錯誤。重新安裝會保留既有設定檔。

`http://127.0.0.1:8081/health` 可查目前值。有限額度模式下，若模型一次提出的工具批次會超出剩餘額度，整批不放行，回報暫停，避免批次跨過上限。

## 可以接續嗎？

原來24次後被中斷的工作，現在可自然跟隨CLI工具流程持續執行，不再因本套件的總工具次數而中斷。已經收到舊停止訊息的對話，輸入：

> 繼續，先檢查目前檔案和測試結果，再處理尚未完成的工作。不要重做已完成的步驟。

新的實際使用者輪次重新計數，舊歷史仍留在對話內；不是刪除歷史或重新開始專案。此計數依請求歷史計算，並非跨上下文壓縮保證不變的永久計數器。

只有重新設定有限額度後，達額度才需要你發出新輪次。現在的無上限模式是讓CLI正常繼續工具流程，不是橋接偽造使用者的「繼續」訊息。模型自行結束、CLI其他限制或重複工具恢復失敗時，仍可能停止；也沒有啟用停止後自動重開對話功能。

連續相同工具的恢復重試與誠實停止維持原樣；取消次數上限不等於改善模型推理或長文查找品質。A→B→A等交替循環未必命中連續相同工具檢查，沒有總次數上限時可能繼續消耗時間。新輪次的重複檢查也重新起算，接續後仍應先查進度。

## 驗證

新增測試涵蓋有限64模式下24次可繼續、64次停止而不呼叫引擎、新使用者輪次恢復、設定熱更新與非法值拒絕、平行工具批次不得超額，以及無上限模式下128次後仍可繼續。也以真實Anthropic HTTP驗證以上核心流程；合成的工具記錄沒有實際執行。原有重複工具恢復及失敗停止測試仍保留。
