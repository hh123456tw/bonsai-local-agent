## 新增實機邊界

- DFlash128K/rk4v4：容量守衛拒絕；DFlash128K/rk2v4-e8 可生成。
- DFlash160K：只剩約327 MiB，未選為預設。
- DFlash144K/rk2v4-e8、prefill256、graph關、draft3：短題181 tok/s，啟動約539 MiB餘裕。
- 基本版256K/rk2v4-e8：改用無額外device checkpoint的catalog、4GiB host cache及有限checkpoint庫，約530 MiB餘裕；短題79 tok/s。
- 以上短題是256 token固定長度測速，finish_reason=length為刻意設定；不是完整任務成功證據。
- 基本版約245,726 token首次讀取301.66秒；三個分散資訊均正確，下一題開頭記錄正確；最後一題中段隨機記錄答錯。HTTP均200，不能只用HTTP狀態判正確。
- 最後一題的開思考復查與DFlash長測結果見相關JSON，原誤答保留，不以重試覆蓋。

較省顯存的KV格式存在精度取捨。256K是模型原生窗口上限，本部署不使用RoPE延伸，也不把較小實體池標成完整256K。

## 最終補驗與採用設定

- DFlash144採4GiB host cache。相同130,427-token資料首次約111秒；追問命中99.9%以上，從2GiB時38.8秒降至4GiB時1.19 / 1.09秒。這修正了本次快取容量導致的延遲，沒有修正同一筆隨機中段記錄的誤答。
- DFlash144三輪的前中後三個顯式資訊與開頭記錄共四項答對；中段隨機記錄答錯。基本版256無思考測試同樣四項答對、一項誤答；開思考重讀後該題答對。無法據此單獨判定是KV精度、模型能力或提示方式的根因。
- 使用4GiB host cache時當次DFlash啟動餘裕約447.5MiB；此前同檔位約539MiB。其他GPU程式會影響餘裕，兩者都不是寬裕顯存配置。
- DFlash144真實OpenCode改檔：17工具、連續重複0次、65.3秒，四項測試外部重跑全過，測試檔逐字未改。舊失敗對話重播第一輪已改用不同指令。
- 基本版256超長輸入返回400/context_length_exceeded；緊接真實生成200/OK，沒有假健康或崩潰。
- 橋接SSE實測中文正確、charset=utf-8、finish_reason=stop和[DONE]均在場。
- 實機切換base256→dflash144通過；忙碌時拒絕切換已驗證；相同配置再次啟動會重用原PID。

啟動器預設DFlash144，另有基本版256K捷徑。兩者是容量與行為已測的配置，不宣稱所有長文精確查找通過；原始誤答紀錄完整保留在tuning。
